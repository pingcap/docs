# タスクフロー

タスクフロー (Task Flow) は {{{ .lake }}} に組み込まれたワークフローオーケストレーション機能です。これにより、SQL ベースのデータパイプラインを有向非巡回グラフ (DAG) として定義、スケジュール設定、監視できます。グラフ内の各ノードは **Task** であり、それぞれ独自のスケジュール、依存関係、実行設定を持つ SQL ステートメントです。**Flow** は複数のタスクをまとめ、自動的に実行順序を管理します。

## 概要 {#overview}

タスクフローは、従来の Task List をより強力なモデルに置き換えるものです。

| 機能 | 従来の Task List | タスクフロー |
| --------------------- | ---------------- | --------- |
| 単一 SQL タスク | ✅               | ✅        |
| 複数タスク DAG | ❌               | ✅        |
| ビジュアルグラフエディタ | ❌               | ✅        |
| バージョン履歴 | ❌               | ✅        |
| ストリームベースのトリガー | ❌               | ✅        |
| 一括操作 | ❌               | ✅        |

## 主要な概念 {#key-concepts}

### Task {#task}

Task は最小の作業単位です。以下を含みます。

- 実行する SQL ステートメント
- スケジュール（手動、間隔、または cron）
- 他のタスクまたはストリームへの任意の依存関係
- 高度な設定（失敗しきい値、結果キャッシュ、最小実行間隔）

### Flow {#flow}

Flow は、依存関係を持つタスクの名前付きコレクションです。{{{ .lake }}} は DAG 構造に基づいて実行順序を自動的に決定します。Flow には以下があります。

- 名前と割り当てられた Warehouse
- 定義済みの依存関係を持つ 1 つ以上のタスク
- ライフサイクル: Created → Started → Suspended → Resumed → Dropped

### DAG (Directed Acyclic Graph) {#dag-directed-acyclic-graph}

タスク間の依存関係グラフです。Task B が Task A に依存している場合、{{{ .lake }}} は最初に Task A を実行し、Task A が成功した後にのみ Task B をトリガーします。循環は許可されません。

## はじめに {#getting-started}

### タスクフローの作成 {#creating-a-task-flow}

1. 左側のサイドバーで **Data** > **Task & Flows** に移動します。
2. 右上隅の **Create** をクリックします。
3. Flow モーダルで、以下を行います。
    - **Flow Name** を入力します。
    - タスクを実行する **Warehouse** を選択します。
4. **Add Task to Flow** をクリックして、最初のタスクを追加します。

### Task の設定 {#configuring-a-task}

タスクフォームで、以下を入力します。

**Basic Settings**

| フィールド | 説明 |
| --------- | ------------------------------------------------------------------------ |
| Task Name | フロー内で一意の名前 |
| Schedule  | 実行タイミング: Manual、Interval（例: 5 分ごと）、または Cron 式 |
| Timezone  | cron スケジュール評価に使用するタイムゾーン |
| SQL       | 実行する SQL ステートメント |
| Comment   | 任意の説明 |

**Dependencies**

| フィールド | 説明 |
| -------------- | ------------------------------------------------------------------- |
| Require Tasks  | このタスクの実行前に完了している必要がある他のタスク |
| Require Stream | このタスクがトリガーされる前に新しいデータを持っている必要があるデータベースストリーム |

**Advanced Options**

| フィールド | 説明 |
| ------------------------------- | ----------------------------------------------------------------------- |
| Suspend Task After Num Failures | N 回連続で失敗した後にタスクを自動的に一時停止します（0 = しない） |
| Enable Query Result Cache       | 冗長な計算を避けるためにクエリ結果をキャッシュします |
| Min Execute Seconds             | 実行間の最小間隔（5s / 10s / 15s / 30s） |

1. **Save** をクリックして、タスクを Flow に追加します。
2. 必要に応じて繰り返してさらにタスクを追加します。タスク間の依存関係を定義するには **Require Tasks** を使用します。
3. **Publish** をクリックして Flow を作成します。

> **Note:**
>
> `account_admin` または Flow 作成者のみが Flow を編集または削除できます。

## Flow の可視化 {#visualizing-the-flow}

Flow を作成した後、その名前をクリックして詳細ページを開きます。**Latest Run** タブに DAG の可視化が表示されます。

各ノードには以下が表示されます。

- Task 名
- 最新の実行ステータス（色分け）
- 実行時間範囲
- エラーメッセージ（失敗時）

**ステータスの色:**

| 色 | ステータス |
| ----------------- | ------------------- |
| 青い枠線 | 予定済み |
| 緑の枠線 | 成功 |
| 赤い枠線 | 失敗 |
| 水色の枠線 | 実行中 |
| 灰色の枠線 | キャンセル済み / 待機中 |

## Flow の管理 {#managing-flows}

### Flow の操作 {#flow-actions}

**Task & Flows** リストでは、各行に次の項目を含むアクションメニューがあります。

| アクション | 説明 |
| --------------------- | ------------------------------------- |
| Edit                  | Flow 名、Warehouse、またはタスクを変更します |
| Suspend               | スケジュールされたすべての実行を一時停止します |
| Resume                | スケジュールされた実行を再度有効にします |
| Execute Once          | 即時の 1 回限りの実行をトリガーします |
| View Runs History     | 過去のすべての実行を表示します |
| View Versions History | 以前のバージョンを参照して比較します |
| Delete                | Flow を完全に削除します |

### 一括操作 {#bulk-operations}

チェックボックスを使用して複数の Flow を選択し、一括操作メニューを使用して以下を実行できます。

- 選択したすべての Flow を一時停止
- 選択したすべての Flow を再開
- 選択したすべての Flow を削除

## 実行の監視 {#monitoring-executions}

### Runs History {#runs-history}

詳細ページの **Runs History** をクリックすると、過去のすべての実行を確認できます。

| カラム | 説明 |
| -------------- | ------------------------------------------------------ |
| Task Name      | 実行されたタスク |
| Warehouse      | 使用された Warehouse |
| State          | Scheduled / Executing / Succeeded / Failed / Cancelled |
| SQL            | 実行された SQL（Query ID リンク付き） |
| Scheduled Time | 実行がトリガーされた時刻 |
| Completed Time | 実行が完了した時刻 |
| Comment        | タスクコメント |

失敗またはキャンセルされた実行にはエラーツールチップが表示されます。エラーをクリックすると、詳細を表示したり、サポートチケットを作成したりできます。

### グローバル Task History {#global-task-history}

**Data** → **Task History** に移動すると、組織内のすべての Flow にまたがる実行を確認できます。以下でフィルタできます。

- Task 名（複数選択）
- 時間範囲（過去 2 日、過去 3 日）

## バージョン管理 {#version-control}

Flow への変更を Publish するたびに、{{{ .lake }}} は新しいバージョンを保存します。バージョン履歴にアクセスするには、以下を実行します。

1. Flow の詳細ページを開きます。
2. **Versions History** タブをクリックします。

### バージョンの比較 {#comparing-versions}

1. チェックボックスを使用して 2 つのバージョンを選択します。
2. **Compare** をクリックします。
3. 2 つのバージョン間で何が変更されたかを示す SQL diff ドロワーが左右並びで開きます。

### 以前のバージョンへの復元 {#reverting-to-a-previous-version}

1. リストからバージョンを選択します。
2. **Revert** をクリックします。
3. ダイアログで操作を確認します。

Flow は選択したバージョンに復元され、新しいバージョンエントリが作成されます。

## スケジュール設定リファレンス {#scheduling-reference}

### スケジュールタイプ {#schedule-types}

**Manual**: Task は **Execute Once** でトリガーされた場合にのみ実行されます。自動スケジュールはありません。

**Interval**: N 分または N 時間ごとに実行します。例: `EVERY 5 MINUTE`。

**Cron**: タイムゾーンをサポートする標準的な cron 式です。例: `0 9 * * 1-5`（平日の午前 9 時）。

### ストリームベースのトリガー {#stream-based-triggers}

Task に **Require Stream** 依存関係がある場合、指定されたストリームに未消費データがあるときにのみ実行されます。これは、テーブル変更（CDC）に反応するイベント駆動型パイプラインの構築に役立ちます。

## ベストプラクティス {#best-practices}

- **シンプルに始める**: 依存関係を追加する前に、まず単一タスクのフローを作成して SQL を検証します。
- **CDC パイプラインには stream を使用する**: stream トリガーと `MERGE INTO` 文を組み合わせて、増分データパイプラインを構築します。
- **失敗しきい値を設定する**: **Suspend Task After Num Failures** を使用して、無制限な再試行による Warehouse クレジットの消費を防ぎます。
- **結果キャッシュを有効にする**: 同じデータを繰り返しクエリするタスクでは、**Query Result Cache** を有効にしてコンピュートコストを削減します。
- **バージョン履歴を活用する**: 大きな変更を加える前に、必要に応じて元に戻せるよう現在のバージョン番号を控えておきます。
- **ワークロードごとに Warehouse を分ける**: より重い変換タスクは大きな Warehouse に割り当て、軽量なタスクは小さな Warehouse に割り当てます。
