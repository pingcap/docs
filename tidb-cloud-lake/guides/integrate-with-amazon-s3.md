# Amazon S3 統合タスク

このページでは、S3 バケットから {{{ .lake }}} にファイルをインポートする Amazon S3 統合タスクを作成する方法について説明します。CSV、Parquet、NDJSON のファイル形式がサポートされており、タスクは一度限りのインポートまたは継続的な取り込みとして設定できます。

再利用可能な AWS 認証情報を先に作成する必要がある場合は、[Amazon S3 - Credentials](/tidb-cloud-lake/guides/aws-credentials.md) を参照してください。

## サポートされるファイル形式 {#supported-file-formats}

| Format  | 説明 |
|---------|--------------------------------------------------------------------|
| CSV     | 区切り文字やヘッダーを設定可能なカンマ区切り値 |
| Parquet | 分析ワークロードに適した、カラム指向のストレージ形式 |
| NDJSON  | 改行区切り JSON。1 行につき 1 つの JSON オブジェクト |

## 前提条件 {#prerequisites}

- **Amazon S3 - Credentials** データソースがすでに作成されていること
- AWS 認証情報に対象の S3 バケットへの読み取りアクセス権があること
- **Clean Up Original Files** を有効にする予定がある場合、認証情報には書き込み権限と削除権限も必要です

## S3 統合タスクの作成 {#creating-an-s3-integration-task}

### ステップ 1: 基本情報 {#step-1-basic-info}

1. **Data** > **Data Integration** に移動し、**Create Task** をクリックします。

2. S3 データソースを選択し、基本設定を構成します。

    | フィールド              | 必須 | 説明 |
    |--------------------|----------|--------------------------------------------------------------------------------------------------|
    | **Data Source**    | はい      | ドロップダウンから既存の **Amazon S3 - Credentials** データソースを選択します |
    | **Name**          | はい      | この統合タスクの名前 |
    | **File Path**     | はい      | オプションのワイルドカードパターンを含む S3 URI（例: `s3://mybucket/data/2025-*.csv`） |
    | **File Type**     | 自動     | ファイル拡張子から自動検出されます。サポート対象: CSV、Parquet、NDJSON |

#### CSV オプション {#csv-options}

ファイルタイプが CSV の場合、追加オプションを利用できます。

| フィールド                | デフォルト | 説明 |
|----------------------|---------|----------------------------------------------------------------|
| **Record Delimiter** | `\n`    | 行区切り文字。オプション: `\n`, `\r`, `\r\n` |
| **Field Delimiter**  | `,`     | カラム区切り文字。カスタム値をサポートします |
| **Has Header**       | Yes     | 先頭行にカラム名が含まれているかどうか。無効にすると、カラム名は `c1`、`c2`、`c3` などとして自動命名されます。 |

#### ファイルパスパターン {#file-path-patterns}

ファイルパスでは、複数のファイルに一致させるためのワイルドカードパターンをサポートしています。

```
s3://mybucket/data/2025-*.csv        # All CSV files starting with "2025-"
s3://mybucket/logs/*.parquet         # All Parquet files in the logs directory
s3://mybucket/events/data.ndjson     # A single specific file
```

### ステップ 2: データのプレビュー {#step-2-preview-data}

基本設定を構成したら、**Next** をクリックしてソースデータをプレビューします。

![S3 Preview Data](/media/tidb-cloud-lake/s3-task-preview-step.png)

システムは最初に一致したファイルを読み取り、次を表示します。

- カラム名と型を含むサンプルデータ
- 一致したファイルの一覧（最大 25 ファイル）とそのサイズ

> **Note:**
>
> 10GB を超えるファイルはプレビュー時にスキップされます。表示されるのは最初の 25 件の一致ファイルのみです。

### ステップ 3: ターゲットテーブルの設定 {#step-3-set-target-table}

{{{ .lake }}} の宛先を構成します。

| フィールド               | 説明 |
|---------------------|--------------------------------------------------------------------|
| **Warehouse**       | インポートの実行に使用する対象の {{{ .lake }}} Warehouse を選択します |
| **Target Database** | {{{ .lake }}} 内の対象データベースを選択します |
| **Target Table**    | {{{ .lake }}} 内のテーブル名 |

![S3 Set Target Table](/media/tidb-cloud-lake/s3-task-set-target-table.png)

システムはソースファイルからカラムを自動検出します。続行する前に、カラム名と型を確認および編集できます。

#### 取り込みオプション {#ingestion-options}

| オプション                       | デフォルト  | 説明 |
|------------------------------|----------|--------------------------------------------------------------------------------------------------|
| **Continuous Ingestion**     | On       | 有効にすると、システムは定期的に（30 秒ごとに）S3 パスをポーリングし、新しいファイルをインポートします |
| **Error Handling**           | Abort    | **Abort**: 最初のエラーで停止します。**Continue**: 失敗した行をスキップしてインポートを継続します |
| **Clean Up Original Files**  | Off      | 有効にすると、インポート成功後に S3 からソースファイルを削除します |
| **Allow Duplicate Imports**  | Off      | 有効にすると、すでにインポート済みのファイルの再インポートを許可します |

> **Tip:**
>
> 新しいファイルが S3 パスに定期的に追加され、それらを {{{ .lake }}} に自動的にロードしたい場合は、**Continuous Ingestion** を有効にしてください。一度限りのインポートの場合は無効にしてください。

統合タスクを確定するには、**Create** をクリックします。

## タスクの動作 {#task-behavior}

| Continuous Ingestion | 動作 |
|----------------------|---------------------------------------------------------------------------------------------------|
| On                   | 継続的に実行され、30 秒ごとに S3 をポーリングして新しいファイルを検出し、自動的にインポートします。 |
| Off                  | 一致するファイルを 1 回だけインポートして停止します。**Allow Duplicate Imports** が有効でない限り、すでにインポート済みのファイルはスキップされます。 |

## 高度な設定 {#advanced-configuration}

### 継続的な取り込み {#continuous-ingestion}

有効にすると、タスクは長時間実行されるプロセスとして動作し、定期的に S3 パスをスキャンして新しいファイルを探します。各サイクルでは次を実行します。

1. ファイルパスパターンに一致するオブジェクトを一覧表示する
2. まだインポートされていない新しいファイルを特定する
3. `COPY INTO` を使用して新しいファイルをターゲットテーブルにインポートする
4. インポート結果をタスク履歴に記録する

これは、上流システムが継続的に新しいファイルを S3 に書き込むデータパイプラインで役立ちます。

### エラーハンドリング {#error-handling}

- **Abort** (default): 最初に発生したエラーでインポートを停止します。データ品質が重要で、続行前に問題を調査したい場合に使用します。
- **Continue**: エラーの原因となる行をスキップし、残りのデータのインポートを継続します。部分的なインポートを許容でき、データスループットを最大化したい場合に使用します。

### Clean Up Original Files (PURGE) {#clean-up-original-files-purge}

有効にすると、ソースファイルは {{{ .lake }}} へのインポート成功後に S3 から削除されます。これにより、ストレージコストの管理や再処理の防止に役立ちます。AWS 認証情報に対象バケットに対する `s3:DeleteObject` 権限があることを確認してください。

### Allow Duplicate Imports (FORCE) {#allow-duplicate-imports-force}

デフォルトでは、システムはどのファイルがインポート済みかを追跡し、後続の実行ではそれらをスキップします。このオプションを有効にすると、以前にインポートされたかどうかに関係なく、一致するすべてのファイルを強制的に再インポートします。これは、スキーマ変更やデータ修正の後にデータを再ロード (load) する必要がある場合に役立ちます。
