# PostgreSQL DDL

PostgreSQL-compatible {{{ .starter }}} supports common PostgreSQL Data Definition Language (DDL) statements for creating and managing database objects.

## Create a table

Use `CREATE TABLE` to create a table:

{{< copyable "sql" >}}

```sql
CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    email TEXT UNIQUE,
    active BOOLEAN DEFAULT true,
    created_at TIMESTAMPTZ DEFAULT now()
);
```

The following common constraints are supported:

- `NOT NULL`
- `DEFAULT`
- `PRIMARY KEY`
- `UNIQUE`
- `REFERENCES` and `FOREIGN KEY`
- `CHECK`

For example:

{{< copyable "sql" >}}

```sql
CREATE TABLE orders (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL REFERENCES users(id),
    amount NUMERIC(10, 2) CHECK (amount >= 0)
);
```

Foreign keys support the following common `ON DELETE` and `ON UPDATE` actions:

- `CASCADE`
- `SET NULL`
- `SET DEFAULT`
- `RESTRICT`
- `NO ACTION`

### Create a table from a query

`CREATE TABLE ... AS SELECT` and `SELECT ... INTO` are supported:

{{< copyable "sql" >}}

```sql
CREATE TABLE active_users AS
SELECT id, name, email
FROM users
WHERE active = true;
```

{{< copyable "sql" >}}

```sql
SELECT id, name
INTO user_names
FROM users;
```

> **Note:**
>
> Tables created using `CREATE TABLE ... AS SELECT` or `SELECT ... INTO` contain an additional `_rowid` primary key column. For details, see [PostgreSQL Compatibility](/tidb-cloud/starter/postgresql-compatibility.md).

### Identity columns

`GENERATED ALWAYS AS IDENTITY` and `GENERATED BY DEFAULT AS IDENTITY` are supported:

{{< copyable "sql" >}}

```sql
CREATE TABLE items (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL
);
```

{{< copyable "sql" >}}

```sql
CREATE TABLE tasks (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title TEXT NOT NULL
);
```

Identity sequence options have compatibility differences. If you need a custom starting value or increment, use an explicit sequence.

For example:

{{< copyable "sql" >}}

```sql
CREATE SEQUENCE order_seq
START WITH 1000
INCREMENT BY 5;

CREATE TABLE sequence_orders (
    id BIGINT PRIMARY KEY DEFAULT nextval('order_seq'),
    description TEXT
);
```

### Generated columns

Stored generated columns are supported:

{{< copyable "sql" >}}

```sql
CREATE TABLE products (
    price NUMERIC,
    tax NUMERIC,
    total NUMERIC GENERATED ALWAYS AS (price + tax) STORED
);
```

## Create an index

B-tree is the default index access method:

{{< copyable "sql" >}}

```sql
CREATE INDEX idx_users_name
ON users (name);
```

Create a unique index:

{{< copyable "sql" >}}

```sql
CREATE UNIQUE INDEX idx_users_email
ON users (email);
```

Expression indexes are supported:

{{< copyable "sql" >}}

```sql
CREATE INDEX idx_users_lower_email
ON users (lower(email));
```

Partial indexes are supported:

{{< copyable "sql" >}}

```sql
CREATE INDEX idx_active_users
ON users (id)
WHERE active = true;
```

`CREATE INDEX CONCURRENTLY` is also supported:

{{< copyable "sql" >}}

```sql
CREATE INDEX CONCURRENTLY idx_users_created_at
ON users (created_at);
```

The following index access methods are supported:

| Index method | Typical use |
| --- | --- |
| B-tree | Equality, range, and ordered lookups |
| GIN | JSONB, arrays, and full-text search |
| HNSW | Approximate nearest-neighbor vector search |

For HNSW index requirements, see [Vector Search](/tidb-cloud/starter/pg-vector-search.md).

For unsupported PostgreSQL index access methods, see [PostgreSQL Compatibility](/tidb-cloud/starter/postgresql-compatibility.md).

### GIN index example

Create a GIN index on a `JSONB` column:

{{< copyable "sql" >}}

```sql
CREATE TABLE documents (
    id BIGSERIAL PRIMARY KEY,
    metadata JSONB
);

CREATE INDEX idx_documents_metadata
ON documents
USING GIN (metadata);
```

Then query JSONB containment:

{{< copyable "sql" >}}

```sql
SELECT *
FROM documents
WHERE metadata @> '{"type":"pdf"}';
```

GIN indexes can also be used for full-text search. For details, see [Full-Text Search](/tidb-cloud/starter/pg-full-text-search.md).

## Create and manage views

Create a view:

{{< copyable "sql" >}}

```sql
CREATE VIEW active_users AS
SELECT id, name, email
FROM users
WHERE active = true;
```

Replace an existing view:

{{< copyable "sql" >}}

```sql
CREATE OR REPLACE VIEW active_users AS
SELECT id, name, email, created_at
FROM users
WHERE active = true;
```

`CREATE OR REPLACE VIEW` can append columns, but it cannot drop or rename existing view columns.

Create and refresh a materialized view:

{{< copyable "sql" >}}

```sql
CREATE MATERIALIZED VIEW user_summary AS
SELECT active, count(*) AS user_count
FROM users
GROUP BY active;
```

{{< copyable "sql" >}}

```sql
REFRESH MATERIALIZED VIEW user_summary;
```

## Alter a table

The following common `ALTER TABLE` operations are supported:

| Operation | Example |
| --- | --- |
| Add a column | `ALTER TABLE users ADD COLUMN phone TEXT;` |
| Drop a column | `ALTER TABLE users DROP COLUMN phone;` |
| Rename a column | `ALTER TABLE users RENAME COLUMN name TO display_name;` |
| Rename a table | `ALTER TABLE users RENAME TO app_users;` |
| Set a default | `ALTER TABLE users ALTER COLUMN active SET DEFAULT true;` |
| Drop a default | `ALTER TABLE users ALTER COLUMN active DROP DEFAULT;` |
| Set `NOT NULL` | `ALTER TABLE users ALTER COLUMN email SET NOT NULL;` |
| Drop `NOT NULL` | `ALTER TABLE users ALTER COLUMN email DROP NOT NULL;` |
| Change a type | `ALTER TABLE users ALTER COLUMN name TYPE VARCHAR(255);` |
| Add a constraint | `ALTER TABLE users ADD CONSTRAINT users_email_unique UNIQUE (email);` |
| Drop a constraint | `ALTER TABLE users DROP CONSTRAINT users_email_unique;` |
| Rename a constraint | `ALTER TABLE users RENAME CONSTRAINT old_name TO new_name;` |

Changing the type of a primary-key column or the referencing column of a foreign key is not supported. For details, see [PostgreSQL Compatibility](/tidb-cloud/starter/postgresql-compatibility.md).

## Drop database objects

Use the following statements to drop database objects:

{{< copyable "sql" >}}

```sql
DROP TABLE IF EXISTS users;
DROP INDEX IF EXISTS idx_users_name;
DROP VIEW IF EXISTS active_users;
DROP MATERIALIZED VIEW IF EXISTS user_summary;
```

`CASCADE` can be used for dependent views and materialized views where applicable:

{{< copyable "sql" >}}

```sql
DROP TABLE users CASCADE;
```

Before dropping a table referenced by a foreign key, remove the referencing foreign-key constraints first. Foreign-key dependency handling differs from PostgreSQL. For details, see [PostgreSQL Compatibility](/tidb-cloud/starter/postgresql-compatibility.md).

## Truncate a table

Use `TRUNCATE` or `TRUNCATE TABLE` for a single table:

{{< copyable "sql" >}}

```sql
TRUNCATE TABLE users;
```

The following PostgreSQL `TRUNCATE` forms are not supported:

- Multi-table `TRUNCATE`
- `CASCADE`
- `RESTRICT`
- `ONLY`
- `RESTART IDENTITY`
- `CONTINUE IDENTITY`

A table referenced by a foreign key cannot be truncated.

## Create and manage schemas

Create a schema:

{{< copyable "sql" >}}

```sql
CREATE SCHEMA app;
```

Create an object in that schema:

{{< copyable "sql" >}}

```sql
CREATE TABLE app.settings (
    key TEXT PRIMARY KEY,
    value TEXT
);
```

Drop the schema when it is no longer needed:

{{< copyable "sql" >}}

```sql
DROP SCHEMA app CASCADE;
```

## Create and manage sequences

Create a sequence:

{{< copyable "sql" >}}

```sql
CREATE SEQUENCE invoice_seq
START WITH 1000
INCREMENT BY 1;
```

Use the sequence:

{{< copyable "sql" >}}

```sql
SELECT nextval('invoice_seq');
```

Use `setval()` to reposition a sequence:

{{< copyable "sql" >}}

```sql
SELECT setval('invoice_seq', 2000);
```

`ALTER SEQUENCE` supports ownership operations such as `OWNER TO` and `OWNED BY`. Other PostgreSQL `ALTER SEQUENCE` options are not supported. For details, see [PostgreSQL Compatibility](/tidb-cloud/starter/postgresql-compatibility.md).

## Other DDL statements

The following common DDL statements are also supported:

| Statement | Description |
| --- | --- |
| `CREATE DATABASE` / `DROP DATABASE` | Create or drop a database. |
| `CREATE TYPE` | Create enum or composite types, with compatibility limitations. |
| `ALTER TYPE` | Supports selected enum operations and `RENAME TO`. |
| `DROP TYPE` | Drop a custom type, with dependency limitations. |
| `CREATE FUNCTION` / `DROP FUNCTION` | Create or drop a function. |
| `CREATE TRIGGER` / `DROP TRIGGER` | Create or drop a trigger. |
| `CREATE COLLATION` / `DROP COLLATION` | Create or drop a collation. |
| `CREATE EXTENSION` / `DROP EXTENSION` | Manage extensions provided by TiDB Cloud. |
| `COMMENT ON` | Add comments to selected object types. |
