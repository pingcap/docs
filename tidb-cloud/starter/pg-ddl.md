# PostgreSQL DDL

PostgreSQL 互換の {{{ .starter }}} は、データベースオブジェクトの作成と管理に使用する一般的な PostgreSQL のデータ定義言語（DDL）文をサポートしています。

## テーブルを作成する {#create-a-table}

テーブルを作成するには、`CREATE TABLE` を使用します。

```sql
CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    email TEXT UNIQUE,
    active BOOLEAN DEFAULT true,
    created_at TIMESTAMPTZ DEFAULT now()
);
```

次の一般的な制約とカラムプロパティがサポートされています。

- `NOT NULL`
- `DEFAULT`
- `PRIMARY KEY`
- `UNIQUE`
- `REFERENCES` と `FOREIGN KEY`
- `CHECK`

例:

```sql
CREATE TABLE orders (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL REFERENCES users(id),
    amount NUMERIC(10, 2) CHECK (amount >= 0)
);
```

外部キーでは、次の一般的な `ON DELETE` および `ON UPDATE` アクションをサポートしています。

- `CASCADE`
- `SET NULL`
- `SET DEFAULT`
- `RESTRICT`
- `NO ACTION`

### クエリからテーブルを作成する {#create-a-table-from-a-query}

`CREATE TABLE ... AS SELECT` と `SELECT ... INTO` をサポートしています。

```sql
CREATE TABLE active_users_snapshot AS
SELECT id, name, email
FROM users
WHERE active = true;
```

```sql
SELECT id, name
INTO user_names
FROM users;
```

> **Note:**
>
> `CREATE TABLE ... AS SELECT` または `SELECT ... INTO` を使用して作成されたテーブルには、追加の `_rowid` 主キーカラムが含まれます。その他の DDL 互換性の違いについては、[PostgreSQLとの互換性](/tidb-cloud/starter/postgresql-compatibility.md) を参照してください。

### IDENTITY カラム {#identity-columns}

`GENERATED ALWAYS AS IDENTITY` と `GENERATED BY DEFAULT AS IDENTITY` をサポートしています。

```sql
CREATE TABLE items (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL
);
```

```sql
CREATE TABLE tasks (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title TEXT NOT NULL
);
```

IDENTITY カラムには、カスタム開始値や増分などのシーケンスオプションに関して互換性の違いがあります。カスタム開始値または増分が必要な場合は、明示的なシーケンスを使用してください。

例:

```sql
CREATE SEQUENCE order_seq
START WITH 1000
INCREMENT BY 5;

CREATE TABLE sequence_orders (
    id BIGINT PRIMARY KEY DEFAULT nextval('order_seq'),
    description TEXT
);
```

### 生成カラム {#generated-columns}

```sql
CREATE TABLE products (
    id BIGSERIAL PRIMARY KEY,
    price NUMERIC,
    tax NUMERIC,
    total NUMERIC GENERATED ALWAYS AS (price + tax) STORED
);
```

## インデックスを作成する {#create-an-index}

B-tree はデフォルトのインデックスアクセスメソッドです。

```sql
CREATE INDEX idx_users_name
ON users (name);
```

一意インデックスを作成します。

```sql
CREATE UNIQUE INDEX idx_users_email
ON users (email);
```

式インデックスをサポートしています。

```sql
CREATE INDEX idx_users_lower_email
ON users (lower(email));
```

部分インデックスをサポートしています。

```sql
CREATE INDEX idx_active_users
ON users (id)
WHERE active = true;
```

`CREATE INDEX CONCURRENTLY` もサポートしています。

```sql
CREATE INDEX CONCURRENTLY idx_users_created_at
ON users (created_at);
```

次のインデックスアクセスメソッドをサポートしています。

| インデックスメソッド | 一般的な用途 |
| --- | --- |
| B-tree | 等価検索、範囲検索、順序付き検索 |
| GIN | JSONB、配列、全文検索 |
| HNSW | 近似最近傍ベクトル検索 |

HNSW インデックスの要件については、[ベクトル検索](/tidb-cloud/starter/pg-vector-search.md) を参照してください。

サポートされていない PostgreSQL のインデックスアクセスメソッドについては、[PostgreSQLとの互換性](/tidb-cloud/starter/postgresql-compatibility.md) を参照してください。

### GIN インデックスの例 {#gin-index-example}

`JSONB` カラムに GIN インデックスを作成します。

```sql
CREATE TABLE documents (
    id BIGSERIAL PRIMARY KEY,
    metadata JSONB
);

CREATE INDEX idx_documents_metadata
ON documents
USING GIN (metadata);
```

次に、JSONB の包含検索を実行します。

```sql
SELECT *
FROM documents
WHERE metadata @> '{"type":"pdf"}';
```

GIN インデックスは全文検索にも使用できます。詳細は、[全文検索](/tidb-cloud/starter/pg-full-text-search.md) を参照してください。

## ビューの作成と管理 {#create-and-manage-views}

ビューを作成します。

```sql
CREATE VIEW active_users AS
SELECT id, name, email
FROM users
WHERE active = true;
```

既存のビューを置き換えます。

```sql
CREATE OR REPLACE VIEW active_users AS
SELECT id, name, email, created_at
FROM users
WHERE active = true;
```

`CREATE OR REPLACE VIEW` ではカラムを追加できますが、既存のビューのカラムを削除したり名前変更したりできません。

マテリアライズドビューを作成して更新します。

```sql
CREATE MATERIALIZED VIEW user_summary AS
SELECT active, count(*) AS user_count
FROM users
GROUP BY active;
```

```sql
REFRESH MATERIALIZED VIEW user_summary;
```

## テーブルの変更 {#alter-a-table}

以下の一般的な `ALTER TABLE` 操作がサポートされています。

| 操作 | 例 |
| --- | --- |
| カラムの追加 | `ALTER TABLE users ADD COLUMN phone TEXT;` |
| カラムの削除 | `ALTER TABLE users DROP COLUMN phone;` |
| カラム名の変更 | `ALTER TABLE users RENAME COLUMN name TO display_name;` |
| テーブル名の変更 | `ALTER TABLE users RENAME TO app_users;` |
| デフォルト値の設定 | `ALTER TABLE users ALTER COLUMN active SET DEFAULT true;` |
| デフォルト値の削除 | `ALTER TABLE users ALTER COLUMN active DROP DEFAULT;` |
| `NOT NULL` の設定 | `ALTER TABLE users ALTER COLUMN email SET NOT NULL;` |
| `NOT NULL` の削除 | `ALTER TABLE users ALTER COLUMN email DROP NOT NULL;` |
| 型の変更 | `ALTER TABLE users ALTER COLUMN name TYPE VARCHAR(255);` |
| 制約の追加 | `ALTER TABLE users ADD CONSTRAINT users_email_unique UNIQUE (email);` |
| 制約の削除 | `ALTER TABLE users DROP CONSTRAINT users_email_unique;` |
| 制約名の変更 | `ALTER TABLE users RENAME CONSTRAINT old_name TO new_name;` |

主キーのカラムの型、または外部キーの参照元カラムの型を変更することはサポートされていません。詳細は、[PostgreSQLとの互換性](/tidb-cloud/starter/postgresql-compatibility.md) を参照してください。

## データベースオブジェクトの削除 {#drop-database-objects}

データベースオブジェクトを削除するには、以下の文を使用します。

```sql
DROP TABLE IF EXISTS users;
DROP INDEX IF EXISTS idx_users_name;
DROP VIEW IF EXISTS active_users;
DROP MATERIALIZED VIEW IF EXISTS user_summary;
```

`CASCADE` を使用すると、ビューやマテリアライズドビューなどの依存オブジェクトを削除できますが、外部キーの依存関係は別途処理する必要があります。

```sql
DROP TABLE users CASCADE;
```

外部キー制約が宙に浮いた状態で残ることを避けるため、テーブルを削除する前に、そのテーブルを参照している外部キー制約を削除してください。外部キー依存関係の処理は PostgreSQL と異なります。詳細は、[PostgreSQLとの互換性](/tidb-cloud/starter/postgresql-compatibility.md) を参照してください。

## テーブルの切り詰め {#truncate-a-table}

単一のテーブルに対しては、`TRUNCATE` または `TRUNCATE TABLE` を使用します。

```sql
TRUNCATE TABLE users;
```

以下の PostgreSQL の `TRUNCATE` 形式はサポートされていません。

- 複数テーブルの `TRUNCATE`
- `CASCADE`
- `RESTRICT`
- `ONLY`
- `RESTART IDENTITY`
- `CONTINUE IDENTITY`

外部キーから参照されているテーブルは切り詰められません。

## スキーマの作成と管理 {#create-and-manage-schemas}

スキーマを作成します。

```sql
CREATE SCHEMA app;
```

そのスキーマ内にオブジェクトを作成します。

```sql
CREATE TABLE app.settings (
    key TEXT PRIMARY KEY,
    value TEXT
);
```

不要になったらスキーマを削除します。

```sql
DROP SCHEMA app CASCADE;
```

## シーケンスの作成と管理 {#create-and-manage-sequences}

シーケンスを作成します。

```sql
CREATE SEQUENCE invoice_seq
START WITH 1000
INCREMENT BY 1;
```

シーケンスを使用します。

```sql
SELECT nextval('invoice_seq');
```

シーケンスの位置を変更するには `setval()` を使用します。

```sql
SELECT setval('invoice_seq', 2000);
```

`ALTER SEQUENCE` は、`OWNER TO` や `OWNED BY` などの所有権操作をサポートしています。その他の PostgreSQL の `ALTER SEQUENCE` オプションはサポートされていません。詳細は、[PostgreSQLとの互換性](/tidb-cloud/starter/postgresql-compatibility.md) を参照してください。

## その他の DDL 文 {#other-ddl-statements}

以下の一般的な DDL 文もサポートされています。

| 文 | 説明 |
| --- | --- |
| `CREATE DATABASE` / `DROP DATABASE` | データベースを作成または削除します。 |
| `CREATE TYPE` | 互換性の制限付きで、enum 型または複合型を作成します。 |
| `ALTER TYPE` | 一部の enum 操作と `RENAME TO` をサポートします。 |
| `DROP TYPE` | 依存関係に制限はありますが、カスタム型を削除します。 |
| `CREATE FUNCTION` / `DROP FUNCTION` | 関数を作成または削除します。 |
| `CREATE TRIGGER` / `DROP TRIGGER` | トリガーを作成または削除します。 |
| `CREATE COLLATION` / `DROP COLLATION` | 照合順序を作成または削除します。 |
| `CREATE EXTENSION` / `DROP EXTENSION` | TiDB Cloud が提供する拡張機能を管理します。 |
| `COMMENT ON` | 一部のオブジェクト型にコメントを追加します。 |
