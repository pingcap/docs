# BYOC リソースプールを一時停止または再開する

アイドル期間中に TiDB Cloud BYOC リソースプールを一時停止することで、データ、バックアップ、ネットワーク設定を保持したまま、データベースのコンピュートコストを削減できます。リソースプールを一時停止すると、プール内のすべてのインスタンスがまとめて一時停止されます。個々のインスタンスを個別に一時停止または再開することはできません。

リソースプールは最大 7 日間一時停止したままにできます。それまでに再開しなかった場合、7 日の上限に達した時点で、TiDB Cloud はリソースプール全体の再開処理を自動的に開始します。

## 開始前に {#before-you-begin}

- `Organization Owner` ロールを持っていることを確認してください。詳細は、[リソースプールを管理する](/tidb-cloud/byoc/manage-resource-pools-byoc.md#required-role) を参照してください。
- リソースプールが **Active** であり、プール内のすべてのインスタンスをオフラインにできることを確認してください。
- プールを一時停止する前に、データのインポートまたはエクスポート、DM、パイプラインまたは changefeed のタスク、アップグレード、キャパシティの変更など、競合する操作を完了または停止してください。
- 一時停止を要求する前に、ワークロードのアクティビティを減らしてください。TiDB Cloud は処理を進める前に、ワークロードのアクティビティやその他の依存関係を確認します。必要なチェックが失敗した場合、または完了できない場合、一時停止は実行されません。

## BYOC リソースプールを一時停止する {#pause-a-byoc-resource-pool}

1. [TiDB Cloud コンソール](https://tidbcloud.com/) で、左側のナビゲーションペインにある **BYOC Management** > **Resource Pools** をクリックします。
2. **Active** のリソースプールを見つけて、その行の **...** をクリックし、**Pause** を選択します。

    または、リソースプール名をクリックして **Resource Pool Details** ページを開き、右上隅の **Pause** をクリックします。

3. **Pause Resource Pool?** ダイアログで、この操作の影響を受けるホスト済みインスタンス数を確認します。
4. （任意）**Create a Manual Backup before pausing** を選択します。

    これを選択すると、TiDB Cloud は一時停止を続行する前に、リソースプール内のすべてのインスタンスに対して手動バックアップを作成します。この処理には長時間かかる場合があります。必須のデータ保護は、このオプションを選択したかどうかにかかわらず実行されます。

5. **Pause Resource Pool** をクリックします。

    TiDB Cloud は、ランタイムコンピュートを削除する前に、必要な保護チェックを完了します。リソースプールが **Paused** になるまで待ちます。リソースプール内のすべてのインスタンスはまとめて一時停止されます。

準備中、TiDB Cloud は必要なチェックと、選択されている場合は手動バックアップを実行します。準備に失敗した場合、リソースプールは **Active** に戻り、ランタイムコンピュートは削除されません。

リソースプールが **Pausing** に入ると、SQL 接続およびアクティブなコンピュートを必要とする操作は利用できなくなります。プール内のすべてのインスタンスが一時停止に参加します。必要なランタイムデータベースコンピュートが削除されると、リソースプールは **Paused** になります。

## 一時停止中の動作 {#behavior-while-paused}

リソースプールが **Paused** の場合:

- プール内のすべてのインスタンスが一時停止されます。データの読み取りや書き込み、またはアクティブなデータベースコンピュートを必要とする操作は実行できません。
- データと、プールの再開に必要な永続ストレージは保持されます。リソースプールは削除されません。
- 既存のネットワーク設定と接続情報は、プール再開後も使用できるよう保持されます。
- 既存のバックアップ、ログ、および履歴メトリクスは、それぞれの保持ポリシーに従って引き続き利用できます。新しいランタイムコンピュートメトリクスは生成されません。
- スケジュールされたバックアップは停止され、新しい手動バックアップは作成できません。
- 一時停止中のプールにインスタンスを作成したり、そこにバックアップを復元したりすることはできません。先にリソースプールを再開してください。
- リソースプールの設定変更およびキャパシティの変更は利用できません。

## BYOC リソースプールを再開する {#resume-a-byoc-resource-pool}

1. [TiDB Cloud コンソール](https://tidbcloud.com/) で、左側のナビゲーションペインにある **BYOC Management** > **Resource Pools** をクリックします。
2. **Paused** のリソースプールを見つけて、その行の **...** をクリックし、**Resume** を選択します。

    または、リソースプール名をクリックして **Resource Pool Details** ページを開き、右上隅の **Resume** をクリックします。

3. **Resume Resource Pool?** ダイアログで、ホストされているすべてのインスタンスへの影響を確認し、**Resume Resource Pool** をクリックします。
4. リソースプールとそのホスト済みインスタンスが **Active** に戻るまで待ちます。

    再開操作には最大 30 分かかる場合があります。リソースプールが **Resuming** の間、SQL 接続は利用できません。

TiDB Cloud がランタイムコンピュートを復元し、準備完了を確認している間、リソースプールとそのインスタンスは **Resuming** に入ります。再開が完了するまで、SQL 接続は利用できません。この処理中は、設定変更およびスケーリング操作も引き続きブロックされます。

プールが **Active** に戻ると、ホストされているすべてのインスタンスも **Active** に戻ります。SQL 接続、スケジュールされたバックアップ、および通常の監視が再開されます。保持されている接続情報を引き続き使用できます。

## 7 日後の自動再開 {#automatic-resume-after-7-days}

連続して一時停止できる最大期間は 7 日間で、リソースプールが **Paused** になった時点から開始されます。**Pausing** に費やした時間はこの上限には含まれません。

期限までにプールを再開していない場合、TiDB Cloud は再開操作を自動的に開始します。リソースプールは **Resuming** に入り、必要な準備完了チェックが完了した後にのみ利用可能になります。

## 課金 {#billing}

BYOC データベース vCPU の料金は、実際にプロビジョニングされているデータベースコンピュートキャパシティに従います。

- **Pausing** 中は、コンピュートノードが削除されるにつれて、データベースコンピュートの料金が下がっていきます。
- **Paused** の間は、データベースコンピュートノードがプロビジョニングされたままではないため、データベース vCPU 料金は 0 です。
- **Resuming** 中は、コンピュートノードが再度プロビジョニングされるにつれて、データベースコンピュートの料金が上がっていきます。

プールが一時停止中でも、保持されているストレージ、ネットワーク、バックアップ、およびクラウドアカウント内のその他のインフラストラクチャに対する料金は継続する場合があります。詳細は、[TiDB Cloud BYOC の料金](/tidb-cloud/tidb-cloud-billing.md#pricing-for-byoc) を参照してください。

## トラブルシューティング {#troubleshooting}

リソースプールが **Pausing** または **Resuming** のまま異常に長時間続く場合、またはプールが **Active** に戻った後も SQL 接続が回復しない場合は、[TiDB Cloudサポート](/tidb-cloud/tidb-cloud-support.md) にお問い合わせください。
