# {{{ .byoc }}} インスタンスを作成する

このドキュメントでは、[TiDB Cloud コンソール](https://tidbcloud.com/) で {{{ .byoc }}} インスタンスを作成する方法について説明します。

TiDB Cloud BYOC (Bring Your Own Cloud) では、コントロールプレーンは TiDB Cloud に保持したまま、データプレーンをお客様自身のクラウドアカウントにデプロイします。BYOC インスタンスを作成する前に、組織で BYOC のオンボーディングを完了し、対象のクラウド環境を準備しておく必要があります。

TiDB Cloud BYOC では、リソースプールが BYOC インスタンスの基盤となる物理リソース、ネットワーク、およびキャパシティを提供します。BYOC インスタンスを作成する前に、対象のクラウドプロバイダーとリージョンにアクティブなリソースプールが存在している必要があります。

> **Note:**
>
> {{{ .premium }}} インスタンスの作成方法については、[{{{ .premium }}} インスタンスを作成する](/tidb-cloud/premium/create-tidb-instance-premium.md) を参照してください。

## 始める前に {#before-you-begin}

TiDB Cloud アカウントをお持ちでない場合は、[こちら](https://tidbcloud.com/signup) をクリックしてアカウントを作成してください。

BYOC インスタンスを作成する前に、次の要件を満たしていることを確認してください。

- TiDB Cloud リソースを作成するために必要な組織またはプロジェクトのロールを持っていること。
- 組織で、対象のクラウドプロバイダーとリージョンに対する前提条件となる BYOC セットアップが完了していること。これには、必要なクラウドアカウント権限が含まれます。AWS の場合、TiDB Cloud が AWS アカウント内で BYOC リソースをデプロイおよび管理するために必要な IAM ロールが含まれます。
- BYOC インスタンスをデプロイしたいクラウドプロバイダーとリージョンに、アクティブなリソースプールが存在していること。

BYOC 環境の準備ができていない場合、**Create Resource** ページに **Bring Your Own Cloud** タブは表示されません。組織で BYOC を有効にするには、TiDB Cloud のアカウントチームまたは [TiDB Cloud Support](/tidb-cloud/tidb-cloud-support.md) にお問い合わせください。

利用可能な適切なリソースプールがない場合、`Organization Owner` は **BYOC Management** > **Resource Pools** またはインスタンス作成フローからリソースプールを作成できます。その他のロールではリソースプールを作成できません。詳細については、[リソースプールを作成する](/tidb-cloud/byoc/create-resource-pool-byoc.md) を参照してください。

## 手順 {#steps}

必要な権限がある場合は、次のように {{{ .byoc }}} インスタンスを作成できます。

1. [TiDB Cloud コンソール](https://tidbcloud.com/tidbs) で [**My TiDB**](https://tidbcloud.com/tidbs) ページに移動し、右上隅の **Create Resource** をクリックします。

2. **Create Resource** ページで、**Bring Your Own Cloud** タブをクリックします。

3. プランとして **BYOC** が選択されていることを確認します。

    BYOC は TiDB X を基盤としており、大規模な本番ワークロード向けに設計されています。データプレーンをお客様自身のクラウドアカウントで実行しながら、自動運用、弾力的なスケーラビリティ、エンタープライズグレードのセキュリティには TiDB Cloud を利用できます。

4. **Basic Settings** エリアで、{{{ .byoc }}} インスタンスの名前を入力し、インスタンスをホストするクラウドプロバイダーとリージョンを選択します。

5. （任意）この {{{ .byoc }}} インスタンスを管理用にプロジェクトへグループ化するには、インスタンスの対象プロジェクトを選択します。

6. **Resource Pool** エリアで、アクティブなリソースプールを選択します。

    選択したクラウドプロバイダーとリージョンに一致し、**Active** ステータスのリソースプールのみが表示されます。適切なリソースプールがなく、`Organization Owner` である場合は、**Create Resource Pool** をクリックして作成します。リソースプールがアクティブになると、新しいインスタンス用に自動的に選択されます。

    十分な vCPU キャパシティを持つリソースプールを選択してください。そうしないと、次の問題が発生する可能性があります。

    - 選択したリソースプールに Pool vCPU Limit が設定されており、現在プロビジョニング済みの vCPU がその上限以上である場合、TiDB Cloud は警告を表示し、そのリソースプールでは {{{ .byoc }}} インスタンスを作成できません。続行するには、そのプールの **Resource Pool** 詳細ページに移動して Pool vCPU Limit を増やすか無効にするか、別のリソースプールを選択してください。
   - 現在プロビジョニング済みの vCPU が Pool vCPU Limit を下回っていても、新しいインスタンスを作成すると、プロビジョニング済み vCPU の合計が上限を超える可能性があります。これにより、リソースのスケーリングが制限され、リソースプール内のすべてのインスタンスのパフォーマンスに影響する可能性があります。必要に応じて、Pool vCPU Limit を増やすか無効にするか、別のリソースプールを選択してください。

7. **Capacity** エリアで、インスタンスの Request Capacity Units (RCUs) の最大数を設定します。RCU は、ワークロードに対してプロビジョニングされるコンピュートリソースを表します。TiDB Cloud は、需要に応じてこの範囲内でインスタンスを自動的にスケールします。

8. {{{ .byoc }}} インスタンスでは、高可用性モードは選択したリソースプールから継承されます。リソースプールがリージョン高可用性を使用している場合、インスタンスもリージョン高可用性を使用します。リソースプールがゾーン高可用性を使用している場合、インスタンスもゾーン高可用性を使用します。BYOC インスタンスの作成時に高可用性モードを設定できません。詳細については、[TiDB Cloud BYOC アーキテクチャ](/tidb-cloud/architecture-concepts.md#tidb-cloud-byoc) を参照してください。

9. **Create** をクリックします。

    インスタンスの作成プロセスが開始されます。プロビジョニング時間は、選択したリージョン、キャパシティ、およびクラウドプロバイダーによって異なる場合があります。

## 次のステップ {#what-s-next}

BYOC インスタンスの作成後は、次の操作を実行できます。

- まだ設定していない場合は、インスタンスの root パスワードを設定またはリセットする。
- アプリケーション環境からインスタンスエンドポイントへのネットワークアクセスを設定する。
- アプリケーションまたは SQL クライアントからインスタンスに接続する。
