# リソースプールを管理する

リソースプールは、TiDB Cloud BYOC インスタンスで使用される基盤となる物理リソース、ネットワーク、およびキャパシティを表します。リソースプール管理を使用すると、リソース使用状況の表示、キャパシティの管理、AWS リソースタグの更新、未使用のリソースプールの削除を行えます。

リソースプールは組織レベルの BYOC リソースであり、プロジェクトには関連付けられていません。

## 必要なロール {#required-role}

リソースプールを管理できるのは、`Organization Owner` ロールを持つユーザーのみです。

他のロールでもリソースプールへの読み取り専用アクセスを持つ場合がありますが、リソースプールの作成、編集、削除、変更はできません。

## リソースプールを表示する {#view-resource-pools}

リソースプールを表示するには、次の手順を実行します。

1. [TiDB Cloud コンソール](https://tidbcloud.com/)で、左側のナビゲーションペインから **BYOC Management** > **Resource Pools** をクリックします。

2. **Resource Pools** ページで、リソースプールの一覧を表示します。

    一覧には、リソースプール名、ステータス、クラウドプロバイダー、リージョン、インスタンス数、作成時刻などの情報が表示されます。

3. リソースプールを絞り込むには、ページ上部の検索ボックスとフィルターを使用します。

4. 一覧を更新するには、更新アイコンをクリックします。

## リソースプールのステータス {#resource-pool-statuses}

リソースプールには次のステータスが表示されます。

- **Creating**: リソースプールをプロビジョニング中です。基本情報は表示できますが、インスタンスの作成や設定変更はできません。
- **Active**: リソースプールを利用可能です。通常の管理操作を実行できます。
- **Modifying**: リソースプールを変更中です。概要、メトリクス、インスタンス、タグ、その他の詳細は表示できますが、インスタンスの作成やキャパシティまたは Pool vCPU Limit の変更はできません。

## リソースプールの詳細を表示する {#view-resource-pool-details}

リソースプールの詳細を表示するには、**Resource Pools** ページでリソースプール名をクリックします。

リソースプールの詳細ページには、次の情報が含まれます。

- **High Availability**: リソースプールがゾーナル高可用性またはリージョナル高可用性のどちらを使用しているかを示します。この値は読み取り専用です。リソースプール作成後に、高可用性モードやアベイラビリティーゾーンの配置を変更できません。
- **Pool vCPU Usage**: 現在プロビジョニングされている TiDB vCPU と追加の vCPU プロビジョニングを表示します。
- **Instances in This Pool**: このリソースプールで実行されている BYOC インスタンスを一覧表示します。
- **Metrics**: vCPU 使用量と物理ストレージ使用量の推移を表示します。
- **Pool Capacity**: TiKV と TiFlash のキャパシティ情報を表示します。
- **AWS Resource Tags**: このリソースプール内のサポート対象リソースに適用されている AWS タグを表示します。

## メトリクスを表示する {#view-metrics}

リソースプール詳細ページの **Metrics** 領域には、次のグラフが表示されます。

- **vCPU Usage Trend**: リソースプールのプロビジョニング済み TiDB vCPU 使用量の推移を表示します。このグラフには現在の vCPU 値も表示されます。
- **Physical Storage Usage Trend**: リソースプールの実際の物理ストレージ使用量の推移を表示します。このグラフには現在のストレージ値も表示されます。

期間を選択して、過去のメトリクスを表示できます。デフォルトでは、過去 30 日間のメトリクスが表示されます。

メトリクスデータを更新するには、**Refresh** をクリックします。

メトリクスデータがまだ利用できない場合、グラフには **No Data Available Yet** と表示されます。

## Pool vCPU Limit を更新する {#update-the-pool-vcpu-limit}

Pool vCPU Limit は、リソースプールに対して許可される最大のプロビジョニング済み TiDB vCPU キャパシティについて、顧客が任意で定義できる上限です。管理ノードや可観測性ノードなどの追加 vCPU プロビジョニングは、この上限には含まれません。

Pool vCPU Limit を更新するには、次の手順を実行します。

1. リソースプールの詳細ページに移動します。
2. **Pool vCPU Usage** 領域で、**Update vCPU Limit** をクリックします。
3. 表示されたダイアログで、**Setup Limit** をオンまたはオフにします。

    - **Setup Limit** をオンにした場合は、新しい Pool vCPU Limit を入力します。
    - **Setup Limit** をオフにした場合は、顧客定義の vCPU 上限はリソースプールに適用されず、課金は引き続き実際の使用量に基づきます。

4. 更新を確認します。

新しい Pool vCPU Limit を設定する場合、その値は `100` vCPU 以上であり、かつ現在プロビジョニングされている TiDB vCPU 以上である必要があります。そうでない場合、更新は拒否されます。

> **Note:**
>
> 現在プロビジョニングされている vCPU が Pool vCPU Limit を下回っている場合でも、インスタンスの作成または復元によって、プロビジョニング済み vCPU の合計がこの上限を超える可能性があります。これにより、リソースのスケーリングが制限され、リソースプール内のすべてのインスタンスのパフォーマンスが低下するおそれがあります。インスタンスを作成または復元する前に、リソースプールに十分な vCPU キャパシティがあることを確認してください。

リソースプールの現在プロビジョニングされている vCPU が Pool vCPU Limit 以上である場合、そのリソースプールではインスタンスを作成または復元できません。インスタンスを作成または復元するには、Pool vCPU Limit を引き上げるかオフにするか、別のリソースプールを選択してください。

リソースプールが **Modifying** ステータスの場合、**Update vCPU Limit** は無効になります。

## キャパシティを更新する {#update-capacity}

リソースプールの TiKV および TiFlash のキャパシティを更新できます。

キャパシティを更新するには、次の手順を実行します。

1. リソースプールの詳細ページに移動します。
2. **Pool Capacity** 領域で、**Update Capacity** をクリックします。
3. **Update _resource-pool-name_ Capacity** ダイアログで、TiKV または TiFlash のキャパシティを更新します。
4. Pool vCPU Limit が設定されている場合は、キャパシティ評価を確認します。
5. **Save** をクリックします。

Pool vCPU Limit が設定されている場合、ダイアログには次のキャパシティ評価情報が表示されます。

- **Current vCPU Usage**: リソースプールの現在プロビジョニングされている TiDB vCPU 使用量。
- **Scaling vCPU Preview**: キャパシティ更新後に見込まれるプロビジョニング済み TiDB vCPU 使用量。
- **Max vCPU Limit**: 現在の Pool vCPU Limit。
- **Scale Evaluation**: 現在の Pool vCPU Limit の下でキャパシティ更新が許可されるかどうか。

Pool vCPU Limit が設定されていない場合、キャパシティ評価情報は表示されません。

次のルールが適用されます。

- TiDB Cloud コンソールではスケールアウト操作のみサポートされています。追加のノード数やサイズ要件がある場合、またはスケールインが必要な場合は、[TiDB Cloud Support](/tidb-cloud/tidb-cloud-support.md) にお問い合わせください。
- TiKV ノード数は 3 台単位で調整する必要があります。
- TiKV ストレージは増加のみ可能です。
- TiKV のマシンタイプは、リソースプール作成後に変更できません。
- TiFlash は任意です。TiFlash が有効になっていない場合、TiFlash ノードはプロビジョニングされません。
- ワークロード要件に応じて、後から TiFlash を有効にできます。
- TiDB Cloud コンソールから TiFlash を無効にできます。TiFlash を無効にすると、リソースプール内のすべての BYOC インスタンスに影響します。TiFlash リソースは削除され、TiFlash に依存する分析ワークロードは利用できなくなるか、パフォーマンスが低下する可能性があります。
- TiFlash のマシンタイプはオンラインで変更できます。
- TiFlash ストレージは増加のみ可能です。
- TiFlash ノード数は増加のみ可能です。
- Pool vCPU Limit が設定されている場合、**Scaling vCPU Preview** は **Max vCPU Limit** を超えてはなりません。

リソースプールが **Modifying** ステータスの場合、**Update Capacity** は無効になります。

## AWS リソースタグを管理する {#manage-aws-resource-tags}

AWS リソースタグは、リソースプール内のサポート対象 AWS リソースに適用されます。

AWS リソースタグを管理するには、次の手順を実行します。

1. リソースプールの詳細ページに移動します。
2. **AWS Resource Tags** 領域で、**Edit Tags** をクリックします。
3. タグを追加、編集、または削除します。
4. 変更を保存します。

次のルールが適用されます。

- タグは、リソースプール内のタグ付け可能なすべての AWS リソースに適用されます。
- タグキーは必須です。
- タグ値は任意です。
- タグキーとタグ値では大文字と小文字が区別されます。
- タグキーは一意である必要があり、大文字と小文字を区別してチェックされます。
- タグキーの長さは 1 ～ 128 UTF-8 文字である必要があります。
- タグ値の長さは 256 UTF-8 文字を超えてはなりません。
- ユーザー定義のタグキーは `aws:` で始めることはできません。
- システム予約済みの AWS タグは上書きまたは編集できません。
- 空の行は無視され、送信されません。
- タグは AWS のタグ付け制限に準拠する必要があります。

## リソースプールの名前を変更する {#rename-a-resource-pool}

リソースプールの名前を変更するには、次の手順を実行します。

1. リソースプールの詳細ページまたは **Resource Pools** ページに移動します。
2. **...** をクリックします。
3. **Rename** をクリックします。
4. 新しい名前を入力し、変更を確認します。

リソースプールの名前変更では表示名のみが変更されます。基盤となるクラウドリソース ID は変更されません。

## リソースプールを削除する {#delete-a-resource-pool}

リソースプールは、BYOC インスタンスが含まれていない場合にのみ削除できます。

リソースプールを削除するには、次の手順を実行します。

1. **Resource Pools** ページに移動します。
2. 削除したいリソースプールを見つけます。
3. **...** > **Delete** をクリックします。
4. 削除を確認するために、リソースプール名を入力します。

リソースプールを削除しても、過去のインスタンスバックアップは削除されません。バックアップ保持期間および Recycle Bin の動作は、既存の BYOC バックアップおよび復元ルールに従います。

## 操作上の制限 {#operation-restrictions}

リソースプールで変更操作が進行中の場合、TiDB Cloud はリソースプールデータをリアルタイムまたはほぼリアルタイムで更新します。この期間中は、次の制限があります。

- リソースプールの概要、メトリクス、インスタンス、タグ、その他の詳細を表示できます。
- インスタンスは作成できません。インスタンスを作成できるのは、リソースプールが **Active** ステータスのときのみです。
- インスタンスが削除可能な状態であれば、削除できます。
- Pool vCPU Limit は更新できません。
- キャパシティは更新できません。

バックエンドでは、操作を送信したときに最終検証が実行されます。操作中にリソースプールの状態が変化した場合、リクエストが拒否されることがあります。
