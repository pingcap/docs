# TiDB Cloud BYOC 自動リージョンデプロイ

AWS 環境の準備が完了し、IAM 権限が確立されると、TiDB Cloud チームが自動プロビジョニングプロセスを開始します。

> **Note:**
>
> このフェーズは TiDB Cloud によって管理され、通常はお客様側での対応は不要です。デプロイが、お客様管理のポリシー、AWS サービスクォータ、またはネットワーク制限によって妨げられた場合、TiDB Cloud チームが支援のためにお客様へ連絡します。

## デプロイの概要 {#deployment-overview}

自動リージョンデプロイは、次の段階で構成されます。

1. コンテナイメージをお客様の AWS アカウントに同期します。
2. リージョン管理プレーンをデプロイします。
3. お客様側のオブザーバビリティおよび関連インフラをデプロイします。
4. 新しい BYOC リージョンを登録して検証します。

このデプロイでは、TiDB Cloud が管理する AWS アカウントと、お客様の AWS アカウントの両方にリソースが作成されます。このフェーズでは、後続のリソースプールおよびインスタンス作成に向けて BYOC リージョンを準備しますが、TiDB のリソースプールやインスタンス自体は**作成されません**。

## ステップ 1: イメージ同期 {#step-1-image-synchronization}

イメージ同期のステップには約 1～2 時間かかります。

**お客様の対応:**

BYOC デプロイ用の AWS リージョンを選択し、そのリージョン情報を TiDB Cloud の担当者に提供してください。

**実行内容:**

TiDB Cloud は、必要なコンテナイメージを中央イメージリポジトリから、お客様の AWS アカウント内の Amazon ECR レジストリへ同期します。

新しい AWS リージョンでの初回デプロイは、必要なすべてのイメージを同期する必要があるため、より時間がかかる場合があります。同じリージョンでの後続のデプロイでは、同期済みのイメージを再利用するため、通常はより早く完了します。

## ステップ 2: リージョン管理プレーンをデプロイ {#step-2-deploy-the-regional-management-plane}

TiDB Cloud は、TiDB Cloud が管理する AWS アカウント内にリージョン管理プレーンをデプロイします。

リージョン管理プレーンには、BYOC 環境のライフサイクル管理に使用されるインフラストラクチャとサービスが含まれます。たとえば、次のようなものです。

- 専用の VPC と Amazon EKS クラスター
- リージョン管理および API サービス
- 設定およびメタデータサービス
- インスタンスのプロビジョニング、スケジューリング、スケーリング、リカバリのためのコンポーネント
- TiDB Cloud グローバルコントロールプレーンとの統合

リージョン管理プレーンには、TiDB アプリケーションデータは保存されません。

## ステップ 3: お客様側の関連インフラをデプロイ {#step-3-deploy-customer-side-supporting-infrastructure}

TiDB Cloud は、アカウントのブートストラップ時に作成された IAM ロールを引き受け、お客様の AWS アカウント内に必要な関連リソースをデプロイします。

これらのリソースには、次のものが含まれます。

- オブザーバビリティ環境用の分離された VPC
- オブザーバビリティサービス用の専用 Amazon EKS クラスター
- メトリクス、ロギング、アラートのコンポーネント
- 関連するストレージ、ロードバランサー、API エンドポイント、DNS レコード、および証明書
- 監査ログおよびサービスレベル指標のリソース
- お客様側環境とリージョン管理プレーン間のセキュアな接続

> **Note:**
>
> このステップで作成される Amazon EKS クラスターは、オブザーバビリティおよびその他の関連サービスをホストします。これは TiDB インスタンスの TiDB データプレーンでは**ありません**。TiDB データプレーンは、TiDB Cloud コンソールで最初の BYOC インスタンスを作成するときに初期化されます。

## ステップ 4: BYOC リージョンを登録して検証 {#step-4-register-and-validate-the-byoc-region}

インフラストラクチャとサービスのデプロイ後、TiDB Cloud は次の処理を行います。

- BYOC リージョンを TiDB Cloud グローバルコントロールプレーンに登録します。
- リージョン管理サービスが正常であることを確認します。
- お客様側のオブザーバビリティ環境への接続性を確認します。
- メトリクスとログが想定された経路を通って流れることを確認します。
- リージョンが TiDB インスタンス作成の準備ができていることを確認します。

## デプロイ完了 {#deployment-completion}

自動リージョンデプロイが完了すると、次の状態になります。

- TiDB Cloud チームから、BYOC リージョンの準備が完了したことが通知されます。
- 新しい BYOC リージョンがインスタンス作成に利用可能になります。
- Amazon EKS、EC2、NAT Gateway、ロードバランサー、ストレージなど、デプロイ中に作成されたお客様所有のリソースに対して、AWS がお客様のアカウントへの課金を開始します。
