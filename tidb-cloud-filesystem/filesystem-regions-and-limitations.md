# TiDB Cloud Filesystem のリージョンと制限事項

TiDB Cloud Filesystem は、以下に示すリージョンと環境でのみ利用できます。ファイルシステムを作成したり、そのデータへのアクセス方法を選択したりする前に、これらの境界を確認してください。

> **Note:**
>
> TiDB Cloud Filesystem は現在パブリックプレビューです。機能およびインターフェースは予告なく変更される場合があります。

## サポートされるリージョン {#supported-regions}

| プロバイダー | 場所 | 正規リージョンコード |
| --- | --- | --- |
| AWS | 北バージニア | `aws-us-east-1` |
| AWS | オレゴン | `aws-us-west-2` |
| AWS | シンガポール | `aws-ap-southeast-1` |
| Alibaba Cloud | シンガポール | `alicloud-ap-southeast-1` |
| Google Cloud | サウスカロライナ | `gcp-us-east1` |
| Microsoft Azure | 米国中部 | `azure-centralus` |

TiDB Cloud Starter は、TiDB Cloud Filesystem が利用できない一部のリージョンもサポートしています。これらのリージョンのいずれかでファイルシステムコマンドを実行すると失敗し、そのリージョンではサービスを利用できないことを示すエラーと、サポートされているリージョンの一覧が表示されます。サポートされるファイルシステムリージョンは、各 `ti` リリースに組み込まれています。サポート対象リージョンが、インストール済みバージョンのリリース後に追加された場合は、`ti` をアップグレードしてください。サービス URL を指定しても、そのリージョンのサポートを有効にすることはできません。

`list` および `describe` のファイルシステムコマンドは、選択したリージョンのみを照会します。リージョンをまたいでリソースを集約することはありません。CLI 全体のリージョン選択と Starter の利用可否については、[TiDB Cloud CLI のリージョン、セキュリティ、および制限事項](/ai/ti/reference/ti-regions-security-and-limitations.md#supported-regions)を参照してください。

## マウントプラットフォームのサポート {#mount-platform-support}

| プラットフォーム | ファイルシステムのマウント | Vault マウント | 要件と代替手段 |
| --- | --- | --- | --- |
| macOS | ファイルシステムのマウントでは、macFUSE がインストールされている場合でも、デフォルトで WebDAV を使用します。FUSE を使用するには、`--driver fuse` を指定します。レイヤーおよびチェックポイントのマウントには FUSE が必要です。 | FUSE | 組み込みの WebDAV ヘルパーはファイルシステムマウントをサポートします。FUSE または Vault マウントには、macFUSE をインストールし、そのシステム拡張を承認してください。 |
| Linux | FUSE | FUSE | `fuse3` パッケージをインストールし、`/dev/fuse` へのアクセスを提供してください。WebDAV マウントはサポートされていません。 |
| Windows | サポートされていません | サポートされていません | 代わりに `ti fs` のデータプレーンコマンドと、マウントを使用しない Vault コマンドを使用してください。 |

FUSE と WebDAV は、バンドルされているファイルシステムランタイムコンポーネントによって実装されています。CLI は別個のネイティブマウント実装にフォールバックしません。実行中のマウントは、開始時に読み込まれたランタイムバージョンを保持します。`ti` を更新した後は、アンマウントしてから再度マウントしてください。

Ubuntu 26.04 では、AppArmor により `fusermount3` も制限されます。マウントパスには `$HOME` または `/mnt` 配下を使用してください。`/workspace` を使用するには、`ti` を root として実行している場合でも、明示的なローカル AppArmor ルールが必要です。セットアップと回避策については、[Linux でファイルシステムをマウントする](/tidb-cloud-filesystem/filesystem-mount-linux.md#ubuntu-2604-mount-path-restrictions)を参照してください。

## 耐久性の境界 {#durability-boundaries}

- デフォルトの FUSE 動作では、コンパニオンが許可する場合に、ローカルバッファリングと非同期のリモート処理を使用します。マウントプロセスを突然終了したり、マシンを削除したりすると、未コミットのメモリまたはライトバック状態が失われる可能性があります。
- `--mount-profile coding-agent` で `coding-agent` マウントプロファイルを選択すると、依存関係ツリー、生成出力、キャッシュ、および Git の内部データはローカルに保存されます。ローカル専用データは、パック化するなどして別途保持しない限り、そのディスクが失われると消失します。
- リモートにコミット済みのファイルシステムデータは、クライアントやサンドボックスが削除されても保持されます。マシンを削除しても、リモートファイルシステムは削除されません。

サポートされている drain と正常なアンマウントのワークフローについては、[安全に終了する](/tidb-cloud-filesystem/filesystem-mount.md#finish-safely)を参照してください。`drain-file-system` は FUSE 専用のオンライン耐久性バリアであり、WebDAV ではサポートされていません。

## 現在の制限事項 {#current-limitations}

- ジャーナルは追記専用であり、現在の公開コマンドにはジャーナル削除コマンドがありません。
- ローカルの認証情報ストアは、プロファイルおよびファイルシステムごとに選択された 1 つのトークンを保持します。すべてのリモートトークンをミラーするわけではありません。既知のトークン ID を持たない古い create または import の認証情報も引き続き使用できますが、リモートトークンのメタデータと関連付けることはできません。
- ファイルシステムの抽出および埋め込みのプロバイダー設定は任意です。未設定のままでも、リソース管理、ファイルアクセス、検索、レイヤー、Git、ジャーナル、vault、またはマウントのワークフローは妨げられません。
- OpenAI プロバイダーインターフェースは、埋め込みおよび画像・音声・動画の抽出でサポートされています。Alibaba Cloud Model Studio Qwen ASR は音声抽出でのみサポートされています。他のベンダーは、厳密に OpenAI 互換コントラクトを通じた場合にのみ条件付きで互換性があります。ネイティブの Anthropic、Gemini、Vertex AI、Bedrock、および Azure OpenAI インターフェースはサポートされていません。
- アプリ管理の埋め込みには、正確に 1024 次元を返すプロバイダーモデルが必要です。`source=database_auto` を報告するファイルシステムは、データベース管理の埋め込みを使用しており、アプリ管理の設定を拒否します。設定手順については、[ファイルシステムの AI プロバイダーを設定する](/tidb-cloud-filesystem/configure-filesystem-ai-providers.md)を参照してください。
- 直接ファイルアクセス、レイヤー、マウント、Git ワークスペース、ジャーナル、および Vault 操作を含むファイルシステムランタイム操作は、`ti` とともにインストールされる、バンドル済みのファイルシステムランタイムコンポーネントに依存します。

トークンまたはマウントの障害については、[TiDB Cloud Filesystem のトラブルシューティング](/tidb-cloud-filesystem/filesystem-troubleshooting.md)を参照してください。コマンド構文とオプションについては、[TiDB Cloud Filesystem CLI コマンドリファレンス](/ai/ti/reference/ti-filesystem.md)を参照してください。
